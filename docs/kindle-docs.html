    Kindle documentation

    Kindle runs Lua mods inside Dark Souls III (version 1.15.2). A mod is a folder with a mod.toml and Lua files; Kindle loads it when the game starts and reloads it the moment you save a file.

    All of these docs are also one page you can open in a browser and search: kindle-docs.html here, installed next to Kindle as docs.html.

    Getting started

    What you need

    • Dark Souls III 1.15.2, the current Steam version. Kindle checks the game version and refuses to run on any other.
    • VS Code with the Lua extension (sumneko.lua), for autocomplete. Optional, but it makes writing mods much easier.

    Installing Kindle

    1. Unzip Kindle-DS3-<version>.zip anywhere, open Kindle Launcher.exe in it, and press Install. It finds Dark Souls III through Steam (or Browse… to its folder) and puts dinput8.dll and the kindle folder into the game's Game folder. Install again from a newer zip to update: your settings and your own mods stay. Without the launcher (on Linux, say), copy dinput8.dll and kindle from the zip into Game yourself (in Steam: right-click Dark Souls III, Manage, Browse local files, then Game).
    2. Start the game from Steam as usual. dinput8.dll loads Kindle as the game starts, and the title screen has Mods. On Linux (Proton), give the game the Steam launch option WINEDLLOVERRIDES="dinput8=n,b" %command% first.
    3. Switch mods on in Mods, on the Mods tab. Bonfire Fate, which comes with Kindle as an example, is off until you do. More mods: Kindle's README.

    While Kindle runs, the game stays off FromSoftware's servers (their terms don't allow modded play online): if the game's Launch Setting (Network settings) is Play Online, Kindle changes it to Play Offline and asks you to restart the game once, since the game reads it as it starts. Kindle's co-op mod connects players without those servers.

    To remove Kindle, delete Game\dinput8.dll and the Game\kindle folder (its backups folder holds copies of your saves, if you want to keep them). Kindle's dinput8.dll takes the place of any other mod's dinput8.dll: Install keeps one that was there as dinput8.dll.before-kindle.

    Kindle Launcher (optional)

    Kindle Launcher.exe, in the kindle folder, starts the game with a choice of mods: Kindle mods, DLL mods (Seamless Co-op, a crash fix) and file mods (folders of replacement game files, through Mod Engine 2). Install sets it up: it finds the game, Mod Engine 2, Seamless Co-op and a crash fix (if installed) and writes launcher.toml with a default profile (a launcher without one shows Find Dark Souls III, which does the same, as does kindle.exe launch --setup). Then Launch (or kindle launch) starts the game with Kindle.

    Each profile has its own Kindle mods, DLL mods (Seamless Co-op, a crash fix) and file mods. Add mods picks Kindle mods from the ones installed, Add DLL and Add folder add the others, and Remove takes any of them out; untick a DLL or file mod to leave it out of the next start. A start runs only the profile's Kindle mods. Switching a mod on or off in game (Pause → Mods) adds it to or removes it from that profile once the game closes. Kindle mods' settings can be changed in the launcher while the game is closed, or in game.

    Profiles. launcher.toml can hold several setups, each with its own DLLs and file mods (folders of replacement game files, like a randomizer's output). Turn a Mod Engine config you already use into a profile with kindle launch --import <name> <config.toml>, list them with kindle launch --list, and start one with kindle launch <name>. In the launcher they're on the left, with New, Rename and Delete. Kindle is always loaded, after the profile's DLLs.

    Without Mod Engine 2 (preview). Untick Mod Engine 2 in the launcher (or kindle launch <name> --direct, or loader = "direct" in a profile): Kindle starts the game and loads the DLLs itself. Profiles with file mods still need Mod Engine 2.

    Mods in the game's title menu and pause menu opens the Mods screen: the game's own settings screen with Kindle's tabs. Kindle holds Kindle's own settings, Mods switches each mod on or off, and Mod menus opens a mod's menu: its buttons (kindle.ui.mod_tab) and its settings. Changes apply at once; Defaults restores a tab's defaults. All mod settings on the Kindle tab opens Kindle's own Mods screen, with every mod and all its settings.

    For mod authors: with Developer overlay on (Mods → Kindle), F1 opens the developer overlay (F1 again closes it). Its tabs show your mods, the log, the player, nearby characters, event flags and params, and Find looks up any name (boss, bonfire, item, place, API function) for its id and the Lua that uses it.

    Your first mod

    kindle\kindle.exe new my-mod

    This makes kindle\mods\my-mod with three files. mod.toml says what the mod is and what it may touch:

    [mod]
id = "my-mod"
name = "My Mod"
version = "0.1.0"
author = "you"
description = "What it does."
api = 1
games = ["ds3"]

[permissions]
modules = ["flags", "items", "player"]

    api is the version of Kindle's Lua API the mod is written for. It only goes up when a change could break existing mods; a mod that needs a newer API than the installed Kindle doesn't load and says so (kindle.api is the running Kindle's). kindle check reminds you if it's missing.

    games says which games the mod is for, by id: ds3 is Dark Souls III (er, Elden Ring, is for Kindle's Elden Ring runtime, not finished yet). Kindle doesn't load a mod in a game its list leaves out, and its log says so. A mod without games is for Dark Souls III, as every mod written before Kindle ran in a second game is.

    Optional keys under [mod]: depends = ["other-mod"] (those mods load first and must be running, or this one doesn't start) and conflicts = ["other-mod"] (this mod won't start alongside them), and enabled = false to keep a mod installed but off.

    Players can change a mod's settings in the overlay's Mods tab. Declare each one in mod.toml and read it with kindle.settings.get:

    [settings.chance]
type = "float"          # "bool", "int", "float" or "choice"
label = "Effect chance"
description = "How often the effect fires."
default = 0.5
min = 0.0
max = 1.0

    local chance = kindle.settings.get("chance")
kindle.on("setting_changed", function(name, value)
  if name == "chance" then chance = value end
end)

    Each API module beyond the basics needs to be listed under modules: flags, items, player, world, params, text, ui, events, hks and debug. A mod can't use a module it didn't ask for, so a mod's mod.toml tells players what it can do. The core functions (kindle.on, timers, ...) and kindle.log are always available.

    main.lua runs when the mod loads:

    local log, player = kindle.log, kindle.player

kindle.on("player_loaded", function()
  log.info("Hello, %s!", player.name())
end)

    .luarc.json points your editor at Kindle's type stubs (see below).

    If the game is running, Kindle loads the new mod within a second. Save any .lua or mod.toml file and the mod reloads: its unload handlers run, its changes to params and text are reverted, and main.lua runs again. An error stops only that mod; the overlay's Mods tab and the log show the file and line, and saving again restarts it.

    A mod can split its code into files: require("util") loads util.lua from the mod's folder (require("lib.math") loads lib/math.lua), once.

    Replacing game files. Put a file in the mod's files folder at its path inside the game's archives, and the game loads it instead of its own: files\chr\c1100.chrbnd.dcx, files\event\m30_00_00_00.emevd.dcx, files\msg\engus\item_dlc2.msgbnd.dcx. No Mod Engine needed. Kindle reads the list when the game starts (restart after adding or removing files); if two mods replace the same file, the first by folder name wins and the log says so. A mod can be only files, with an empty main.lua. Map files (files\map\..., such as mapstudio\m30_00_00_00.msb.dcx) work too, at any size.

    Editor setup

    Open the mod's folder in VS Code (File > Open Folder) with the Lua extension installed. You get:

    • completion and docs for the whole API as you type kindle.;
    • event names in kindle.on(", and each event's handler arguments (e. in a damage handler lists target, attacker, attack_power, attack_id);
    • item, animation and bonfire names: kindle.items.give(" lists every item in your game;
    • param tables and their fields: kindle.params.get("EquipParamWeapon", id). lists the weapon param's fields;
    • warnings for typos and wrong argument types.

    The names come from kindle\stubs\kindle-game.lua, which Kindle writes from your own game (in its language) the first time you load into the world. The editor indexes it once; give it a few seconds after opening the folder.

    For a mod folder you made by hand, add a .luarc.json with the path to your stubs:

    {
  "runtime": { "version": "Lua 5.4" },
  "workspace": { "library": ["C:/Program Files (x86)/Steam/steamapps/common/DARK SOULS III/Game/kindle/stubs"] },
  "diagnostics": { "globals": ["kindle"] }
}

    The console

    Try code in the running game before putting it in a mod. The console is off until you turn it on: in kindle\kindle.toml, under [runtime], set console = true and restart the game. Then:

    kindle\kindle.exe console

    Type Lua and press Enter; the result is printed (tables too). The console has every module, with no permissions needed, and keeps your variables between lines. Code can span lines: start a function, if or table and the console waits (...) until it's finished. Lines starting with : are commands: :mods lists mods, :reload [id] reloads them, :log [n] shows the last log lines, :run <file> runs a Lua file, :help lists the rest. Without the interactive console: kindle run "kindle.player.hp()" for one line, kindle run -f test.lua for a file.

    The console only listens on your own machine (127.0.0.1, port 27850 by default). Any program on the PC can use it while it's on, so turn it off again when you stop writing mods.

    Sharing a mod

    kindle\kindle.exe check my-mod
kindle\kindle.exe pack my-mod

    check reads mod.toml with the same rules Kindle uses, compiles every Lua file, and checks each use of the API: misspelled functions (with a suggestion), modules used without their permission, and permissions listed but never used. Names given as text are checked too: events, settings (declared in mod.toml), required files and pictures (in the mod's folder), and, once Kindle has written kindle\stubs\kindle-game.lua from your game, param tables and the fields of a row kept in a local (local row = kindle.params.get("EquipParamWeapon", id), then row.weight), and the keys of an options table written into the call (kindle.world.spawn{ enemy = "wolf", ai_enabled = false }). pack runs the same check and, if it passes, writes my-mod-<version>.zip holding the mod's folder (without editor files), ready to unzip into someone else's kindle\mods. Both take a mod's folder or its id.

    What mods can't do

    Mods run in a sandbox: Lua's table, string, math, utf8 and coroutine libraries, plus Kindle's API. There's no network, OS or debug access, no file access but reading the mod's own folder (kindle.read_data), and no loading of compiled bytecode. Each call into a mod (an event handler, a timer) has a time limit (200 ms by default, script_time_limit_ms in kindle.toml), so an infinite loop is stopped instead of freezing the game, and each mod can use up to 128 MB of memory.

    To remember something between sessions, use kindle.store: values per character (save slot) or for the mod itself, which Kindle saves under kindle\data\<mod id>.

    Changes a mod makes to params and text are undone when it unloads. Changes to the game world (items given, flags set, souls) are real and saved with the character, like anything else that happens in game.

    Events and hooks

    A mod's main.lua runs once, when the mod loads. Everything after that happens in handlers: functions the mod registers to be called when something happens in the game.

    local handle = kindle.on("player_died", function()
  kindle.log.info("You died.")
end)

kindle.cancel(handle) -- stop listening

    Every kindle.on, timer, flag watcher and menu option returns a handle for kindle.cancel. All of them are removed when the mod unloads, so a mod never needs to clean up its handlers itself.

    Kinds of event

    Lifecycle

    EventWhen
    player_loadeda character entered the world: after loading a save, and again after load screens where the game rebuilds the player. If one already is when the mod loads (or reloads), right away.
    player_unloadedthe character leaves the world (load screen, quitting to the menu).
    unloadthe mod is about to be reloaded or removed. Undo anything the game won't undo for you.
    setting_changedthe player changed one of the mod's settings in the overlay: fun(name, value).
    map_loadingthe game is about to read an area's file: fun(map, file), file "map" (what stands where) or "events" (its event scripts). Changes made now (params, kindle.maps, kindle.events) are in place for this load; the loading screen waits for the handlers (10 seconds at most).
    frameevery frame, with the seconds since the last one.

    Most game functions only work while a character is loaded; kindle.player.loaded() tells you. A common shape:

    kindle.on("player_loaded", function()
  -- set up per-load state here
end)

    Game events

    Kindle notices these by checking the game's state once per frame, and only while some mod listens for them. They report what happened; they can't change it.

    EventHandlerWhen
    player_diedfun()the player died
    region_changedfun(new, old)the player moved to another play region (ids)
    character_killedfun(character)a non-player character's HP reached 0
    character_spawnedfun(character)a non-player character appeared (created, or the area's enemies coming back when the player rests); not those already there when the player arrives
    item_gained / item_lostfun(item, count, name)the player's inventory changed
    effect_applied / effect_expiredfun(id)an SpEffect started or ended on the player
    level_upfun(level, old_level, raised, souls)the soul level rose (the game's level-up screen, or a script): raised maps each attribute that rose to its new value ({ vigor = 13 }), souls is how many souls went with it
    equipment_changedfun(slot, item, old)what an equipment slot holds changed (a kindle.slot; item or old is nil for an empty slot). Checked every few frames
    spells_changedfun(spells, old)the attuned spells changed: both lists of goods items, in slot order
    souls_changedfun(souls, old)the souls held changed (a kill, a purchase, a level, dying)
    bonfire_litfun(bonfire)a bonfire was lit for the first time (a kindle.bonfire). Checked twice a second
    menu_opened / menu_closedfun(kind)one of the game's menus opened or closed: "esc" (the Esc menu) or "menu" (any other: a bonfire's, a talk's, a shop, level up...)
    ember_changedfun(embered)the player was embered (true) or lost it (false)
    key_pressedfun(key)the player pressed a key, a controller button or a mouse button: its name, as kindle.input.down takes ("f5", "pad_y", "mouse_middle"). Not while a screen or window of Kindle's has the input. For a mod's hotkey
    bonfire_restedfun(bonfire)the player sat down at a bonfire (bonfire is a kindle.bonfire, or nil)
    bannerfun(name, type)the game showed one of its banners, e.g. "you_died" (see kindle.banner)
    boss_barfun(shown, name, entity)the game's event scripts showed a boss's health bar (shown true: a boss fight began) or hid it (the boss died, or the fight reset when the player died): the name the bar shows (nil if none) and the boss's entity id. Bars a mod shows with kindle.events.run aren't reported
    shop_buyfun(item, count, row)the player bought count of item in a shop (ShopLineupParam row); it reports the purchase, it can't undo it
    travelfun(map, entity, how)the game began sending the player somewhere, before the warp and any loading screen: how "bonfire" (a bonfire's travel, the menu's or kindle.bonfire.warp; entity the bonfire's) or "script" (an event script's warp: a boss arena's way out, the Path of the Dragon; entity the player start it goes to); map the area, e.g. "m40_00_00_00". It reports the travel, it can't stop it
    boss_defeatedfun(kind)a boss fell: "heir_of_fire" or "lord_of_cinder" (the game's own HEIR OF FIRE DESTROYED / LORD OF CINDER FALLEN banners)

    Event flags have their own watchers: kindle.flags.on_set(id, fn) and kindle.flags.on_clear(id, fn).

    Hooks

    Hooks run while the game is doing the thing, so a handler can change the outcome. They get one table, e, describing it:

    EventeThe handler can
    damagetarget, attacker, attack_power, attack_idassign e.attack_power to change the hit; return false to cancel it
    animationcharacter, name, idassign e.name or e.id to play another animation; return false to cancel it
    effecttarget, source, idassign e.id to apply another SpEffect; return false to block it
    item_usedplayer, item, namereturn false to keep the item (its effect still happens)
    item_lotlotassign e.lot to roll another item lot, return false for nothing: map pickups (an area's all at once as it loads, so also during loading screens), enemy drops (as the enemy dies), event and boss rewards. A cancelled pickup still shows but gives nothing. The game also gives the rows right after the lot (lot+1, lot+2 ... up to the first missing row; a boss reward and its soul are two such rows) in the same roll: the event fires once, for the first. Lots mods award (events.award_item_lot) pass through them too, just before they're given
    -- Halve all damage the player takes.
kindle.on("damage", function(e)
  if e.target and e.target.is_player then
    e.attack_power = e.attack_power / 2
  end
end)

    Hooks fire for every character, so check who's involved (is_player, kind, name, entity_id). Some fire very often: animation and effect many times a frame. Keep these handlers short and return early when the event isn't one you care about.

    The game runs hooks on its own worker threads. Kindle runs mods one at a time; if another mod is busy when a hook fires, Kindle waits a few milliseconds and then lets the game carry on without your handler. That's rare, but a mod shouldn't rely on seeing every single animation or effect.

    For anything slow, or anything that calls back into the game heavily, let the hook record what happened and do the work later, from a timer:

    kindle.on("animation", function(e)
  if e.character.is_player and e.name == "W_Rolling" then
    kindle.after(0, function() kindle.player.add_souls(10) end) -- runs on the next frame
  end
end)

    Behaviour scripts

    The hks module hooks the characters' behaviour scripts (the HavokScript that decides what a character does from moment to moment): kindle.hks.on_env changes the answers those scripts get from the game, and kindle.hks.on_act watches or blocks what they do. Edited scripts can call mods with kindle(name, ...), handled by kindle.hks.on_call. See the hks reference.

    Characters in events

    Characters arrive as tables (kindle.character): a snapshot of name, hp, position, kind and so on at that moment. To act on the character later, pass the table (or its handle) to a kindle.world function, which looks the character up again:

    kindle.on("character_killed", function(c)
  kindle.log.info("%s died at %.0f m", c.name or c.model, c.distance or 0)
end)

    Timers

    kindle.after(5, function() kindle.ui.toast("Five seconds later") end)
local h = kindle.every(60, function() kindle.ui.toast("A minute passed") end)

    Times are real seconds, checked once per frame. kindle.every keeps running until you cancel it or the mod unloads, so start repeating timers once (or cancel the old one first), not every time player_loaded fires:

    local timer
kindle.on("player_loaded", function()
  if timer then kindle.cancel(timer) end
  timer = kindle.every(60, tick)
end)

    Errors

    An error in any handler stops the mod: Kindle logs it (with file and line), runs the mod's unload handlers, reverts its param and text changes, and marks it failed in the overlay. Save a file to start it again. For calls that may fail for reasons outside your control (an item name that isn't in the player's language, a character that's gone), use pcall:

    local ok, err = pcall(kindle.items.give, "Uchigatana")
if not ok then kindle.log.warn("couldn't give it: %s", err) end

    Each handler also has a time limit (200 ms by default); one that runs longer is stopped as an error, so a mistake can't freeze the game.

    Cookbook

    Short, complete examples. Each one lists the permissions its mod.toml needs.

    Reward a boss kill

    Permissions: flags, items

    kindle.flags.on_set(kindle.flags.boss.iudex_gundyr, function()
  kindle.items.give("Ember") -- shows the game's "item received" box
end)

    Every boss has a named flag (kindle.flags.boss.*, from the game's own event scripts) and so does every bonfire (kindle.flags.bonfire.firelink_shrine, lit). Not sure of an item's exact name? Search from the console: kindle.items.find("estus").

    Take less damage, deal more

    Permissions: none (hooks are core)

    kindle.on("damage", function(e)
  if e.target and e.target.is_player then
    e.attack_power = e.attack_power * 0.5
  elseif e.attacker and e.attacker.is_player then
    e.attack_power = e.attack_power * 1.5
  end
end)

    Souls for every kill

    Permissions: player

    kindle.on("character_killed", function(c)
  if c.kind == "enemy" then
    kindle.player.add_souls(100)
  end
end)

    Warn at low HP

    Permissions: player, ui

    local warned = false
kindle.every(0.5, function()
  if not kindle.player.loaded() then return end
  local low = kindle.player.hp() < kindle.player.max_hp() * 0.25
  if low and not warned then
    kindle.ui.toast("Low HP!", { color = "red" })
  end
  warned = low
end)

    A bonfire menu option

    Permissions: ui, player

    -- The Handmaid's shop stock: ShopLineupParam rows 110000-119899.
local HANDMAID_FIRST, HANDMAID_LAST = 110000, 119899

kindle.ui.add_menu_option {
  text = "Kindle's blessing",
  where = "bonfire",
  on_select = function()
    kindle.ui.menu {
      { text = "Restore HP and FP", on_select = function() kindle.player.heal() end },
      { text = "Refill estus", on_select = function() kindle.player.refill_estus() end },
      { text = "Open the Handmaid's shop", on_select = function() kindle.ui.shop(HANDMAID_FIRST, HANDMAID_LAST) end },
    }
  end,
}

    The option appears in every bonfire's menu; picking it opens a list in the game's own menu style, and the shop entry opens the game's shop over those ShopLineupParam rows. With where = "npc" it works the same in the menus of NPCs whose menu opens a screen (a shop, reinforcing, levelling up ...): Andre, the Fire Keeper, the Shrine Handmaid and others.

    A menu of your own

    Permissions: ui

    local options = kindle.store.get_global("options") or { damage = 1.0, hard = false, motto = "" }
local function save() kindle.store.set_global("options", options) end

local function open_options()
  kindle.ui.screen {
    title = "Hard Mode",
    subtitle = "Changes apply at once",
    rows = {
      { header = "Enemies" },
      { text = "Damage", help = "How hard they hit.", slider = { min = 0.5, max = 3, step = 0.25 }, value = options.damage,
        on_change = function(v) options.damage = v; save() end },
      { text = "One life", toggle = options.hard, on_change = function(on) options.hard = on; save() end },
      { text = "Motto", input = options.motto, max = 24, on_change = function(text) options.motto = text; save() end },
      { header = "More" },
      { text = "Reset", on_select = function()
          kindle.ui.confirm { title = "Reset?", on_yes = function() options = { damage = 1.0, hard = false, motto = "" }; save() end }
        end },
    },
  }
end

kindle.ui.add_menu_option { text = "Hard Mode", where = "bonfire", on_select = open_options }

    A screen of the mod's own, in the game's menu style, over everything: up and down move, left and right change a switch, choice or slider, Enter (A) picks, Esc (B, a right click) goes back; the mouse hovers and clicks. Rows are buttons (on_select), sub-screens (screen = {...} or a function returning one), switches, choices (choices = {...}), sliders, text typed in (input), a key the player picks by pressing it (key = "f6", for a hotkey the mod then hears through key_pressed), lines of text (info = true, with a value on the right for a stat) and headings. screen:update(spec) redraws it in place. kindle.ui.choose and kindle.ui.confirm are two ready-made ones: a pick from a list, and a yes or no. Opened from a bonfire's menu, the screen is back at that menu when it closes; kindle.ui.title_entry("Hard Mode", "Its options.", open_options) puts the same screen on the title's main menu.

    A longer screen can have tabs, as the game's own menus do: tabs = {{title = "Enemies", rows = {...}}, {title = "Player", rows = {...}}} in place of rows. LB and RB (Q and E, or a click on a tab's title) turn them; tab = 2 opens on the second, and on_tab(index, title) hears the player turn.

    Draw on the screen

    Permissions: ui, world

    local hud = kindle.ui.layer()
kindle.on("souls_changed", function(souls)
  hud:set { { text = "Souls: " .. souls, x = 1880, y = 40, align = "right", color = "#d8b46a" } }
end)

-- Bars over the enemies near the player, five times a second.
local marks = kindle.ui.layer()

    Put another enemy in an area

    Permissions: maps

    -- Every enemy of one model in a map becomes an enemy of another map's type. The models here
-- are examples: list a map's parts with kindle.maps.parts(map) in the console to find yours.
local HERE, MODEL = "m30_00_00_00", "c1100"
local FROM_MAP, FROM_MODEL = "m31_00_00_00", "c1240"

local function first_enemy(map, model)
  for number, part in ipairs(kindle.maps.parts(map) or {}) do
    if part.kind == "enemy" and part.model == model then return number end
  end
end

kindle.on("map_loading", function(map, file)
  if map ~= HERE or file ~= "map" then return end
  local donor = first_enemy(FROM_MAP, FROM_MODEL)
  local changes = {}
  for number, part in ipairs(kindle.maps.parts(HERE)) do
    if donor and part.kind == "enemy" and part.model == MODEL then
      changes[#changes + 1] = { replace_enemy = number, from = { map = FROM_MAP, part = donor } }
    end
  end
  kindle.maps.edit(HERE, changes)
end)

    The new enemy stands where the old one stood, on the same ground, and walks its route, but it's its own type: its stats, AI, looks and drops. Its spot's event scripts (waking, ambushes) no longer act on it. Changes made in map_loading are in place for the load that's starting; made elsewhere, from the next time the area loads.

    Tour 0: the loop

    Every tour uses this loop. It is quick, and the rest builds on it.

    Make the mod. kindle new my-mod --mods <the game's kindle\mods folder> makes three files:

    FileHolds
    mod.tomlthe mod's id, name, version, api = 1, games = ["ds3"], and [permissions] modules, the parts of the API it may use
    main.luathe code; this one logs "Hello, !" when a character loads
    .luarc.jsonpoints the Lua language server at Kindle's API stubs (the stubs folder next to kindle.exe, or next to the mods folder), so the editor autocompletes kindle. and flags misspellings. With neither found, its library list is empty: add the path to dist\stubs yourself

It prints my-mod: ok (1 Lua file(s)) or the errors (listed in When a mod goes wrong). Run it after every step.     Load it. Start the game with Kindle. Mods in kindle\mods load at the start, in folder-name order. With the game running, a new folder loads as soon as it appears, and saving any of the mod's files reloads it: unload handlers run, everything the mod changed is undone, and main.lua runs again.

    Choices. A mod can live anywhere while you write it. Point --mods at the game's folder so a save reloads it at once, or write it elsewhere and copy it in. kindle pack my-mod checks the mod and zips it to share.

    Tour 1: Hard mode

    A challenge run: hits hurt more, Estus is capped, sprinting is off, and deaths are counted on screen. Each part is a setting, so the player picks their own challenge. The finished mod: ex-hard-mode.

    Step 1: the first setting and the damage hook

    mod.toml:

    [mod]
id = "ex-hard-mode"
name = "Example: Hard Mode"
version = "1.0.0"
api = 1
games = ["ds3"]

[permissions]
modules = ["player"]

[settings.damage_taken]
type = "float"
label = "Damage taken"

default = 1.5
min = 1.0
max = 5.0

    main.lua:

    kindle.on("damage", function(hit)
  if hit.target and hit.target.is_player then
    hit.attack_power = hit.attack_power * kindle.settings.get("damage_taken")
  end

    The damage hook runs as every hit lands, on anyone. hit.target is the character hit, and is_player is true for your own. Assigning hit.attack_power changes the hit before the target's defence is applied. The setting is read on every hit, so a change in the Mods screen applies to the next one.

    Try it. Check, load, take a hit. Open Esc, then Mods, and the setting is a slider from 1.0 to 5.0.

    Choices. Another way to make the game harder is params: raise every NpcParam row's attack, or lower the player's defence. That applies everywhere at once, but each change is a table walk.     Step 2: the Estus cap, with a timer

    [settings.estus_cap]
type = "int"
label = "Estus at most"
description = "Estus Flask charges you can hold; extra charges are taken away. 15 leaves them alone."
default = 3
min = 0
max = 15

    return
  end

    player.estus() is {hp, hp_max, fp, fp_max}: the charges of the Estus and Ashen Estus Flasks and their allotments. set_estus(hp, nil) sets the first and leaves the second alone.

    Choices. There's no event for "the flask was refilled". Charges come back at a bonfire, from an Estus Shard, or from a script. So the mod looks once a second and corrects. Three things looked possible:

    • item_used returning false: it keeps the item, but the drink still heals. No good for blocking Estus.
    • bonfire_rested: catches the refill at a bonfire, but not the others.
    • kindle.every(1, ...): catches all of them within a second, for one call a second. Chosen.

    kindle.player.loaded() guards the title screen and loading screens, where there is no player to read.

    Step 3: no sprinting, with an hks block that comes and goes

    [settings.no_sprint]
type = "bool"
label = "No sprinting"
description = "The sprint button does nothing: you run at most."
default = true

    Add "hks" to the modules, then:

    local SPEED_VARIABLES = { MoveSpeedLevelReal = true, MoveSpeedIndex = true }
local sprint_block = nil

local function apply_sprint_setting()
  local wanted = kindle.settings.get("no_sprint")
  if wanted and not sprint_block then
    sprint_block = kindle.hks.on_act(kindle.hks.act.SET_VARIABLE, function(call)
      if call.character and call.character.is_player and SPEED_VARIABLES[call.args[1]] then
        return false
      end
    end)
  elseif not wanted and sprint_block then
    kindle.cancel(sprint_block)
    sprint_block = nil
  end
end

kindle.on("setting_changed", function(name)
  if name == "no_sprint" then
    apply_sprint_setting()
  end
end)

apply_sprint_setting()

    The character's behaviour script (HavokScript, c0000.hks for the player) picks the move speed with act(SET_VARIABLE, name, value). hks.on_act sees each of those calls, and returning false refuses it. With MoveSpeedLevelReal and MoveSpeedIndex refused, the speed stays at a run.

    Choices.

    • The handler could stay registered and check the setting inside. Instead it's added and removed with the setting (kindle.cancel(handle)), because these calls are frequent and run on the game's script threads. With the setting off, the mod adds nothing to them.
    • kindle.debug.trace_hks(true) logs the player's script calls with their names. That is how to find the call behind any other move you want to block: turn it on, do the move, read the log.
    • input.block_actions(true) would block every action button, not just sprint.

    Tour 2: Run timer

    A speedrun clock, splits at bosses and first bonfire rests, best times, and a menu of its own in the Mods screen. The finished mod: ex-run-timer.

    Step 1: a clock that survives quitting

    local run = nil

local function clock(seconds)
  seconds = math.floor(seconds)
  local hours, minutes = seconds // 3600, seconds % 3600 // 60
  if hours > 0 then
    return string.format("%d:%02d:%02d", hours, minutes, seconds % 60)
  end
  return string.format("%d:%02d", minutes, seconds % 60)
end

kindle.on("player_loaded", function()
  run = kindle.store.get("run")
  if not run then
    run = { start = kindle.player.play_time(), splits = {} }
    kindle.store.set("run", run)
  end
end)

kindle.on("player_unloaded", function()
  run = nil
  kindle.ui.status(nil)
end)

kindle.every(0.5, function()
  if run then
    kindle.ui.status(clock(kindle.player.play_time() - run.start))
  end
end)

    Choices. Which clock?

    • kindle.player.play_time() is the save's play time. It survives quitting, stops in the title screen and is the same number the game shows. Chosen.
    • kindle.time() is seconds since Kindle started. It keeps counting in menus and starts over with the game.
    • kindle.clock() is the computer's clock (seconds since 1970) and kindle.date() its date. Right for a daily seed or a date in a log; wrong for a run's time, which shouldn't count the hours the game was closed. (A mod's Lua has no os library; these two are its wall clock.)

    every(0.5) rather than every frame: the text changes once a second, so twice a second is enough to keep it from looking late.

    Step 2: splits from game events

    local BOSS_SPLITS = { heir_of_fire = "Heir of fire destroyed", lord_of_cinder = "Lord of cinder fallen" }

local function split(name)
  if not run then return end
  local time = kindle.player.play_time() - run.start
  run.splits[#run.splits + 1] = { name = name, time = time }
  kindle.store.set("run", run)
  kindle.ui.toast(string.format("%s  %s", name, clock(time)))
end

kindle.on("boss_defeated", function(kind)
  split(BOSS_SPLITS[kind] or kind)
end)

kindle.on("bonfire_rested", function(bonfire)
  if bonfire and bonfire.name then
    split("Bonfire: " .. bonfire.name)
  end
end)

    boss_defeated comes from the game's own banner, so it fires for every boss the game announces. bonfire_rested passes the kindle.bonfire (id, name, lit, flag ...).

    Choices.

    • Bosses by banner or by flag. boss_defeated gives no name. For named splits, flags.on_set(kindle.flags.boss.iudex_gundyr, fn) fires on one boss's defeat flag (needs flags). Banners suit "every boss"; flags suit a route.
    • Only the first rest. The finished mod skips a bonfire already in the run's splits, and has a setting to turn bonfire splits off.

    Try it. Rest at two bonfires, then rest at the first again. Two splits, not three, once the first-rest check is in.

    Tour 3: Practice tool

    Save a spot (you and the enemies near you), go back to it whenever you like. The finished mod: ex-practice-tool.

    Step 1: save and load where you stand

  local x, y, z = kindle.player.position()
  local estus = kindle.player.estus()
  return { x = x, y = y, z = z, facing = kindle.player.facing(), hp = kindle.player.hp(), fp = kindle.player.fp(),

    Choices. player.teleport(x, y, z) moves you within the loaded map, at once. player.warp(bonfire) goes through a loading screen to a bonfire, the game's own way. For practising a fight, teleport. For "back to the start of the area", a warp.

    Step 2: the enemies, by entity id

    Add "world":

    Step 4: a shortcut, and cleanup

    Add "input":

    local held_for = 0

      held_for = -math.huge -- once per hold

    input.held knows "left", "right" and "action", from the pad or the keyboard. Both directions at once is a combination nothing in the game uses. Setting the counter to minus infinity makes it fire once per hold, then resets when you let go.

    Tour 4: New weapon

    A longsword of your own, made from the Long Sword. The finished mod: ex-new-weapon.

    Step 1: the row

    modules = ["params"]:

    Choices. Which id? Weapon ids carry the upgrade level in the last digits (+1 is id + 1) and the infusion in the hundreds (Heavy is + 100).     Choices. How the player gets it:

    • items.give on load: simple, once per character. Chosen.
    • A shop: a ShopLineupParam row (equipType = 0 for a weapon) and ui.shop from a bonfire option, as ex-new-item-shop does for goods.
    • A pickup in the world: an ItemLotParam row's slot pointing at it (category 0 for weapons).

    Tour 5: Pickup shuffle

    Items lying in the world trade places, from a seed. The finished mod: ex-pickup-shuffle.

    Step 1: find the pickups

    modules = ["params"]:

    local function int(value) return math.tointeger(value) or 0 end

local lots = {}
for _, id in ipairs(kindle.params.rows("ItemLotParam")) do
  local row = kindle.params.get("ItemLotParam", id)
  if int(row.getItemFlagId) > 0 and int(row.LotItemCategory01) == 0x40000000 then
    lots[#lots + 1] = id
  end
end
kindle.log.info("%d one-time goods lots", #lots)

    An item lot is an ItemLotParam row: up to eight slots (ItemLotId1..8 the item, LotItemCategory01..08 its kind, LotItemNum1..8 how many, LotItemBasePoint01..08 its weight in the lottery) and getItemFlagId, the flag set when it's picked up. A flag above 0 means "given once": a pickup, a one-time drop or a reward. 0x40000000 in the category means goods.

    Choices. Which lots? The finished mod also requires:

    • slot 1 only, so a lot is one item;
    • the goods row's goodsType in the chosen kinds (0 consumables, 2 materials, 5 spells), never 1 (key items), so the game stays finishable;
    • not a flask or multiplayer item (goods below 240), and not a boss soul (700 to 799);
    • no row at id - 1 or id + 1: the game gives a lot's following rows with it, and a chain shouldn't be split.

    Each rule is a line of if. Run the mod after each and watch the count in the log: 552 lots for consumables.

    Step 2: a seeded shuffle

    local function generator(seed)
  local state = seed
  return function(limit)
    state = state ~ (state << 13)
    state = state ~ (state >> 7)
    state = state ~ (state << 17)
    return (state >> 1) % limit + 1
  end
end

local function shuffled(list, seed)
  local next_number = generator(seed)
  local order = table.move(list, 1, #list, 1, {})
  for i = #order, 2, -1 do
    local j = next_number(i)
    order[i], order[j] = order[j], order[i]
  end
  return order
end

    Choices. math.random with math.randomseed(seed) would work too. The mod's own xorshift is a few lines, gives the same numbers for a seed on every PC and every Lua build, and isn't moved by any other use of math.random in the mod. For a shared seed ("play seed 42"), that matters. The shuffle is Fisher-Yates: each order equally likely.

    Step 3: move the contents, keep the flags

    Add a seed int setting, then:

    local sources = shuffled(lots, math.tointeger(kindle.settings.get("seed")))
local moves = {}
for i, lot in ipairs(lots) do
  moves[i] = { sources[i], lot }
end
kindle.params.copy("ItemLotParam", moves, { "getItemFlagId" })

    params.copy(table, pairs, keep) copies each {from, to}, every to getting what its from held before any of them changed, except the fields in keep. Keeping getItemFlagId keeps "picked up" with the place. A place you've already looted stays looted, and nothing can be picked up twice.

    Choices. Three ways to move pickups:

    • Copy rows (params.copy), as here: one call, the lottery of each lot moves whole, undone on unload.
    • Write slots (row.ItemLotId1 = ...): for putting items of your choosing in places. Kindle's own randomizer writes single-item lots this way when an item moves into a lot from a shop.
    • The item_lot hook (e.lot = other): decided per roll. The rolled lot sets its own flag, so for one-time pickups it needs a new lot per place carrying the original's flag. That suits drops that come back better than pickups.

    Step 4: when it applies, and a new seed

    local function apply()
  kindle.params.reset("ItemLotParam")
  -- find the lots, shuffle, copy (steps 1 to 3)
end

kindle.on("setting_changed", function(name)
  if name == "seed" or name == "kinds" then apply() end
end)

apply()

    The game rolls an area's pickups as the area loads. The mod's first apply() runs at its start, before any area loads, so the whole game is shuffled. A seed changed later applies as each area next loads. params.reset("ItemLotParam") puts back what this mod wrote, so a new seed shuffles the game's world and not the last shuffle.

    Try it. Turn on the spoiler setting and read the list in the log. Pick up the first item of the game. Change the seed, rest (the area reloads), and the next pickups are different.

    Porting a Dark Souls III mod to Elden Ring

    When a mod goes wrong: the messages and what they mean

    A mod can fail at three points: kindle check on your PC, loading when the game starts, or running when one of its handlers hits an error. This page lists the messages each one gives, with the mistake that causes it and the fix.

    The kindle check messages were captured on 2026-11-03 from twenty deliberately broken mods (kindle check <folder>). The runtime messages are quoted from Kindle's source, with the parts that vary in angle brackets.

    Contents: 1. What happens to a mod with an error · 2. kindle check: mod.toml · 3. kindle check: the Lua · 4. What kindle check doesn't catch · 5. Errors while the mod runs · 6. A routine for a broken mod

    1. What happens to a mod with an error

    • kindle check prints error: lines (the mod won't work) and warning: lines (it will, but something is off), then a total. A clean mod prints <id>: ok (<n> Lua file(s)).
    • Loading. A mod whose mod.toml doesn't parse, or whose main.lua errors as it runs for the first time, isn't started. The error goes to logs\kindle.log in the kindle folder.
    • Running. An error in any handler (an event, a timer, a button) stops the whole mod. Kindle writes the error to kindle.log, shows a toast for 10 seconds (<mod name> stopped: <first line of the error> (F1 > Log)), unloads the mod and undoes what it changed in the game (param writes, text, hooks). The Mods screen shows it as failed. Save the fixed file and Kindle reloads the mod.
    • Too slow. A call that runs longer than script_time_limit_ms (200 ms of CPU time by default, in kindle.toml) is stopped with script exceeded its time limit (see script_time_limit_ms), and the mod stops as above. This guards the game against an endless loop.

    Because one error stops everything, a handler that might fail on bad data (a row that may not exist, a character that may have gone) is better checked than trusted. See section 5.

    5. Errors while the mod runs

    Check what may be missing. params.get returns nil for a row that doesn't exist, and world.character returns nil for a character that isn't loaded. Indexing nil (row.weight) is an error that stops the mod: attempt to index a nil value (local 'row').

    local row = kindle.params.get("EquipParamWeapon", id)
if not row then
  kindle.log.warn("no weapon row %d: skipped", id)
  return
end
row.weight = 0

    Catch what you can't check. pcall(fn, ...) runs fn and returns false, message on an error instead of stopping the mod. The text pack example uses it for items named in English: a game in another language has no "Homeward Bone", and the rename is an error there.

    local ok, err = pcall(kindle.items.set_name, "Homeward Bone", "Bone of Return")
if not ok then
  kindle.log.warn("couldn't rename the Homeward Bone: %s", err)
end

    Read the log. The error line in logs\kindle.log starts with the mod's id and what was running (the event or the file), then the message, which for an error in your Lua begins with the file and line (main.lua:12: attempt to index a nil value). The traceback is left out, to keep it to one line. In the game, with Developer overlay on (Mods, the Kindle tab), F1 opens the developer overlay, whose Log tab shows the same lines.

    Memory. A mod's Lua can use up to 128 MB. A table that grows every frame and is never emptied reaches it eventually, and the mod stops with Lua's "not enough memory".

    The console. kindle console (or kindle run "<lua>") runs Lua in the game while it's running: try the failing call there with the same arguments and see what it returns. Turn it on first: console = true under [runtime] in kindle\kindle.toml, then restart the game. The console is its own mod, so an error there doesn't stop yours.

    6. A routine for a broken mod

    1. kindle check <folder>. Fix every error: and read every warning:.
    2. Start the game. If the mod isn't in the Mods screen, look in kindle.log for its id: a mod.toml that didn't parse, or not loaded: it's for <games>, not <this game>.
    3. If it shows as failed, the toast and the log say why. Fix and save; Kindle reloads it.
    4. If it runs but does nothing, add kindle.log.info lines at each step (the handler fired, the value read, the row changed) and watch the log. A handler that never fires is often an event name that exists but means something else: player_loaded fires once per character load, not on every respawn.
    5. Try the one call that matters in kindle console, with the values from the log.

    on

    kindle.on(event: kindle.event, fn: function) -> integer

    Subscribe to an event. frame handlers receive the seconds since the last frame. player_loaded fires when a character is in the world: once the loading screen is over (and immediately on (re)load if one already is). unload fires before the mod is reloaded or removed.

    Game events (polled each frame, only while something is subscribed):

    • player_died()
    • region_changed(new, old) play region ids
    • character_killed(character) a non-player character's HP reached 0
    • character_spawned(character) a non-player character appeared (one created, or the area's enemies coming back when the player rests); not the characters already there when the player arrives in an area. Checked every few frames.
    • item_gained(item, count, name) / item_lost(item, count, name) inventory changes
    • effect_applied(id) / effect_expired(id) SpEffects on the player
    • level_up(level, old_level, raised, souls) the soul level rose (at the game's level-up screen, or by a script): raised maps each attribute that rose to its new value ({ vigor = 13 }), souls is how many souls went with it (the cost)
    • equipment_changed(slot, item, old) what a slot holds changed (kindle.slot; item or old nil for an empty slot): equipping, unequipping, a weapon swapped by a script. Checked every few frames.
    • spells_changed(spells, old) the attuned spells changed (lists of goods items, slot order)
    • souls_changed(souls, old) the souls held changed (a kill, a purchase, a level, dying)
    • bonfire_lit(bonfire) a bonfire was lit for the first time (a kindle.bonfire). Checked twice a second.
    • menu_opened(kind) / menu_closed(kind) one of the game's menus opened or closed: kind "esc" (the Esc menu) or "menu" (any other: a bonfire's, a talk's, a shop, level up...)
    • ember_changed(embered) the player was embered (true) or lost it (false)
    • key_pressed(key) the player pressed a key, controller button or mouse button (kindle.key; not while a screen or window of Kindle's is open)
    • bonfire_rested(bonfire) the player sat down at a bonfire; bonfire is the kindle.bonfire rested at (nil if unknown)
    • shop_buy(item, count, row) the player bought count of item in a shop (ShopLineupParam row); the souls are already being taken: it reports, it can't undo
    • banner(name, type) the game showed one of its banners (see kindle.banner)
    • boss_defeated(kind) a boss fell: "heir_of_fire" (HEIR OF FIRE DESTROYED) or "lord_of_cinder" (LORD OF CINDER FALLEN), from the game's own banner
    • boss_bar(shown, name, entity) the game's event scripts showed (a boss fight began) or hid (it ended: the boss died, or the player did and the fight reset) a boss's health bar: the name it shows (nil if it has none) and the boss's entity id

    Hooked events (run as the game does it, so handlers can change the outcome):

    • damage(e) every hit on any character. e.target, e.attacker (characters), e.attack_power (before the target's defence; assign to change the hit), e.attack_id (AtkParam row). Return false to cancel the hit.
    • animation(e) every animation event any character starts: e.character, e.name (e.g. "W_Rolling"), e.id. Assign e.name or e.id to play something else instead; return false to cancel it. Fires often: keep handlers quick.
    • effect(e) an SpEffect about to be applied to any character: e.target, e.source (characters), e.id. Assign e.id to apply a different effect; return false to block it. Fires often (many effects are re-applied every frame): keep handlers quick.
    • item_used(e) a player used a goods item (as it takes effect): e.player, e.item, e.name. Return false to keep the item (it still takes effect).
    • item_lot(e) an item lot about to be rolled: map pickups (all of an area's, as it loads, so also during loading screens), enemy drops (as the enemy dies), and event and boss rewards. e.lot (ItemLotParam row); assign it to roll another lot, return false for nothing (a cancelled pickup still shows but gives nothing). The rolled lot's own pickup flag is the one the game sets. The game also gives the rows right after the lot (lot+1, lot+2 ... up to the first missing row; a boss reward and its soul are two such rows), in the same roll: this fires once, for the first. Lots mods award (events.award_item_lot) pass through them too, just before they're given.

    Changes an event, all or nothing.     kindle.hks

    Needs the "hks" permission in mod.toml.

    The character behaviour scripts (HavokScript, c0000.hks etc.). They ask the game questions with env(id, ...) and act with act(id, ...); mods can change the answers and block actions without editing the scripts. Use kindle.debug.trace_hks(true) to see the player's calls (known ids are named). Example: blocking act SET_VARIABLE for "MoveSpeedLevelReal" stops the player sprinting.

    Functions

    • on_env: Change the answer to env(id, ...): return a number/boolean (nil keeps the game's answer).
    • run_act: Have a character's script perform act(id, ...): it runs at that script's next call (within a frame).
    • ask_env: Ask a character's script env(id, ...); the last argument is fn(result) for the answer (nil if the character's script didn't run within ~5 seconds).
    • eval: Run HKS source in a character's script state, with access to its globals and functions (the script's own Lua, not Kindle's).
    • get_variable: Read a behaviour graph variable (the values the animation graph runs on, e.g.
    • set_variable: Set a behaviour graph variable.
    • get_global: Read a global of the character's script, e.g.
    • set_global: Set a global of the character's script (nil removes it).
    • on_call: Handle kindle(name, ...) calls from edited behaviour scripts.
    • on_act: Watch or block act(id, ...): return false to block the action.

    A param table's name, e.g. "EquipParamWeapon". Each table also has a row type of the same name listing its fields.
